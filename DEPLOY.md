# Deploying a test build (for iPhone / device testing)

This fork's built-in deploy workflows (`deploy.yml`, `github-pages.yml`, …) are
gated with `if: github.repository == 'pagefaultgames/pokerogue'`, so they do **not**
run on a fork. To test changes on a real device — for example the iOS save-export
fix, which only activates on an iPhone in Safari over **HTTPS** — deploy the branch
to a free static host that gives you an `https://…` URL.

## Why a copy step is needed

`pnpm build` does not bundle the game's assets or locales (vite's `publicDir` is
`false` for builds). On the official server those are served alongside the build.
So any standalone static deploy must place the `assets/` and `locales/` git
submodule contents into the publish directory at the web root:

```
pnpm build && cp -r assets/. dist/ && mkdir -p dist/locales && cp -r locales/. dist/locales/
```

The build also needs the submodules checked out (the i18n build plugin reads
`locales/en` at build time), so make sure your host fetches git submodules — they
are public, so no deploy keys are required.

## Option 1 — Netlify (recommended, turnkey)

`netlify.toml` in the repo root already encodes the build command, publish dir,
and Node version. Steps:

1. Sign in to <https://app.netlify.com> with GitHub.
2. **Add new site → Import an existing project** → pick `SungHyunC/pokerogue`.
3. Set the **branch to deploy** to `claude/iphone-pocketlog-support-NEMDS`
   (or your default branch). Build settings are read from `netlify.toml`.
4. Deploy. Netlify clones submodules automatically and gives you an
   `https://<site>.netlify.app` URL.
5. Open that URL in iPhone Safari → **Menu → Manage Data → Export** to verify the
   share sheet appears and the `.prsv` file can be saved to the Files app.

## Option 2 — Cloudflare Pages

Configure these in the Pages dashboard (build settings are not file-based):

- **Build command:** `pnpm build && cp -r assets/. dist/ && mkdir -p dist/locales && cp -r locales/. dist/locales/`
- **Output directory:** `dist`
- **Environment variable:** `NODE_VERSION = 24.9.0`

> ⚠️ Cloudflare Pages caps a deployment at **20,000 files**. PokéRogue's full asset
> set may exceed this, in which case the deploy will fail. If so, prefer Netlify
> (Option 1), which has no comparable hard file-count limit.

## Login / accounts (offline mode)

A self-hosted copy **cannot** use the official account server. The production build
points at `https://api.pokerogue.net`, whose CORS policy only allows the official
`pokerogue.net` origin, so login requests from a Netlify/Cloudflare domain are
blocked by the browser and fail.

`netlify.toml` therefore sets `VITE_BYPASS_LOGIN=1`, which runs the game in offline
mode: no login required, with saves stored in the browser's `localStorage`. Use the
in-game **Manage Data → Export / Import** (the iOS-friendly flow) to back up saves
or move them between devices — e.g. export from desktop `pokerogue.net` and import
into your offline iPhone build.

(Cloudflare Pages users: set `VITE_BYPASS_LOGIN = 1` as an environment variable in
the Pages dashboard to get the same behavior.)

If you instead want real accounts/cloud saves, you'd have to self-host the PokéRogue
backend (`rogueserver`) and point `VITE_SERVER_URL` at it — that's a much larger
undertaking and out of scope here.

## Notes

- The `manifest.json` file fetched at startup is generated by the official server's
  `prmanifest` tool and won't exist on these hosts. The app handles its absence
  gracefully (it only affects asset cache-busting) — you'll see a harmless
  "Manifest not found" log.
- These hosts auto-redeploy on every push to the configured branch, so you can keep
  iterating and just refresh on the phone.
